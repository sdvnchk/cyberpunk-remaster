# Changelog

## 1.10.0
- В Rule Elements добавлены характеристики STR/DEX/CON/INT/WIS/CHA в список «На какую проверку / selector».
- Для FlatModifier/ActiveEffectLike выбор характеристики изменяет нативный `system.abilities.<ability>.mod` через ActiveEffectLike.
- Для Strike выбор характеристики записывается в `ability`; для SpecialStatistic — в `attribute`.
- Добавлена защита от создания заведомо нерабочего ability-selector для несовместимых Rule Elements.

## 1.6.0

- Добавлено поле **«Уровень предмета»** (0–30).
- Уровень записывается в нативное поле SF2e `system.level.value`.
- При загрузке существующего импланта уровень автоматически подхватывается.
- Уровень сохраняется в пользовательских пресетах и JSON-профилях.
- Уровень отображается в предпросмотре конструктора.

## 1.5.0

- Traits активации заменены на выбор из каталога системы с поиском.
- Выбранные traits отображаются тегами и удаляются по одному.
- Добавлена возможность вручную вводить кастомные trait slugs.
- Traits активации сохраняются в пресетах и профилях.

## 1.4.0

- Добавлена отдельная вкладка **«Активация / эффект»**.
- Активация поддерживает 1/2/3 действия, свободное действие и реакцию.
- Добавлены traits, требования, триггер, частота и лимит использований.
- Добавлена длительность временного SF2e Effect и ручное отключение.
- Rule Elements активируемого эффекта не применяются пассивно к импланту.
- Все пресеты Rule Elements можно направлять либо в пассивные правила, либо в активируемый Effect.
- Добавлена выдача состояний/эффектов/предметов по UUID через `GrantItem` при активации.
- На лист предмета добавляются кнопки **«Активировать»** и **«Отключить эффект»**.
- Добавлена необязательная запись активации в чат.
- Профили/пользовательские пресеты сохраняют настройки активации и Effect.

## 1.3.0

- Окно конструктора теперь можно свободно перетаскивать по экрану за заголовок; растягивание за угол сохранено.
- Цена больше не добавляется в канонический текст описания импланта.
- Цена записывается в штатное поле SF2e `system.price.value.sp` (в Remaster это числовой носитель эдди).
- Добавлен выбор размера предмета (`tiny/sm/med/lg/huge/grg`) с записью в `system.size`.
- Добавлена масса/Bulk: 0, лёгкая (0.1), стандартные значения и произвольное число; запись в `system.bulk.value`.
- При загрузке Item-шаблона нативные цена, размер и Bulk подтягиваются обратно в конструктор.
- Цена, размер и Bulk сохраняются в пользовательских пресетах.

## 1.13.5
- Пользовательские готовые модели ПКТ переведены с отдельного DOM-каталога CIC на штатный каталог моделей Remaster.
- CIC теперь подмешивает пользовательские модели непосредственно в `CyberwareTab.loadPktContent()` / `pktModels`.
- Установка пользовательской модели использует штатную схему компонентов Remaster: `pktModelKey`, `pktComponentKey`, `pktLocked`, `pktBodyId`, `pktFamily`, `pktParentFamily`, `pktReplaceableBase`.
- Компоненты установленной модели нельзя извлечь или деактивировать отдельно: сначала требуется штатная кнопка «Демонтировать».
- Корпус ПКТ нельзя извлечь, пока на нём установлена модель.
- Карточка модели после установки автоматически становится штатной карточкой «Установлено компонентов: N / Демонтировать».
- Кнопка «Установить модель» использует штатный диалог Remaster со списком компонентов, Потерей Человечности и пояснением Hard Cost.
- Базы и модули после установки отображаются в штатных разделах ПКТ и связываются через `pktModuleLinkUpdates`.
- Добавлен API `registerPktModelFromData(data)` для пакетной регистрации моделей из структурированных `pktPrerequisites`.
- `createFromData()` теперь действительно создаёт Item мира/Actor, а не только возвращает исходные данные Item.
