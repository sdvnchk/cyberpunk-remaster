# Cyberpunk Remaster — Конструктор имплантов

## Полное руководство пользователя v1.13.31

Это руководство рассчитано на пользователя, который впервые открыл Foundry VTT и не знает Rule Elements, JSON или UUID. Внутри Foundry Cyberpunk Remaster автоматически создаёт Journal Entry **«Cyberpunk Implant Creator — Полный мануал»** с отдельными страницами. В конструкторе также есть кнопка **«Мануал»**.

## Быстрый старт
1. Включите Cyberpunk Remaster.
2. Откройте **Предметы / Items**.
3. Нажмите **Конструктор имплантов**.
4. На вкладке **Основное** задайте название, картинку, тип Item, уровень, Stress/Hard Cost.
5. Создайте простой тестовый Item.
6. Перетащите его на тестового персонажа.
7. Только после проверки добавляйте Rule Elements, ПКТ и активацию.

## Что умеет конструктор
- Equipment-импланты;
- нативные Weapon и Armor;
- базы и модули ПКТ;
- Stress/Hard Cost и проверка установки;
- нативные уровень/редкость/цену/размер/Bulk;
- пассивные Rule Elements;
- временные Rule Elements через активацию;
- Action на листе Actor;
- UUID-ссылки, @Check и inline-roll в описаниях;
- пользовательские пресеты и JSON-профили.

## Ссылки перетаскиванием
Поля **Основное описание** и **Описание эффекта активации** являются drop-zone. Перетащите туда Item, способность, черту, заклинание или эффект из Items/Compendium. Конструктор вставит `@UUID[...] {Название}`. После создания Item Foundry покажет кликабельную ссылку.

Если перетаскивание источника не содержит UUID, используйте ручное поле UUID во вкладке «Описание / проверки».

## Вкладка «Основное»
**Шаблон** — исходный Item, структура которого сохраняется.  
**Профиль** — готовая начальная настройка типа импланта/ПКТ.  
**Куда создать** — Items мира или конкретный Actor.  
**Название / картинка** — обычные данные Item.  
**Тип импланта** — база, модуль, внутренний, внешний, стилевой.  
**Тип Item SF2e** — equipment, weapon или armor.  
**Уровень / редкость / цена / размер / Bulk** — нативные поля Item.  
**Hard Cost** — числовая стоимость по Remaster.  
**Stress Cost** — формула вроде `2d6` или полный `[[/r ...]]`.  
**Проверка** — например `@Check[flat|dc:5|showDC:all]`.  
**Слоты** — вместимость базы или стоимость модуля.

## Оружие
Выберите тип Item `weapon`. Заполните категорию, Grade, группу, baseItem, урон, тип урона, range, reload, usage, боезапас, traits, материал, HP/твёрдость. JSON patch используйте только если нужного поля нет в UI.

## Броня
Выберите тип Item `armor`. Заполните категорию, Grade, группу, baseItem, AC Bonus, Dex Cap, штрафы, Strength, traits, материал, HP/твёрдость.

## Механика / ПКТ
Здесь задаются установленность, traits, ПКТ-флаги, family/parentFamily, эксклюзивная семья, качество, человечность и UUID выдаваемых Item. Для модуля `parentFamily` должен соответствовать `family` подходящей базы.

## Описание и проверки
Можно писать текст и HTML, вставлять `@Check[...]`, `[[/r ...]]`, `@UUID[...]`. Способности и предметы можно перетащить непосредственно в описание.

## Активация
Для временных режимов включите активацию, задайте действие, traits, requirements/trigger, частоту, длительность, имя/картинку Effect. Rule Elements эффекта работают только пока временный Effect существует.

## Rule Elements простыми словами
Rule Element — JSON-инструкция системе. `key` определяет тип правила, `selector` — цель, `value` — величину, `predicate` — условие, `path` — путь данных для ActiveEffectLike.

Пример +1 к Стойкости:
```json
{"key":"FlatModifier","selector":"fortitude","type":"item","value":1}
```

### Выносливость / Stamina
Готовый пресет меняет максимум SP:
```json
{
  "key":"ActiveEffectLike",
  "mode":"add",
  "path":"system.attributes.hp.sp.max",
  "value":5,
  "phase":"afterDerived"
}
```
Он меняет максимум, а не текущее расходуемое SP.

## Пресеты и JSON-профили
Пользовательский пресет сохраняет заполненную форму. JSON-профиль удобен для резервной копии, переноса между мирами и обмена шаблонами.

## Диагностика
Если правило не работает: проверьте, что Item на Actor, проверьте key/selector/path/predicate/phase, затем удалите последнее сложное правило и тестируйте по одному. Если модуль обновлялся, удаляйте старую папку перед установкой новой сборки.

## Словарь
**Actor** — персонаж/NPC. **Item** — предмет/способность/эффект. **UUID** — уникальный адрес документа. **Rule Element** — правило автоматизации. **Selector** — цель правила. **Predicate** — условие. **Path** — путь данных. **Effect** — временный Item. **JSON patch** — низкоуровневое изменение данных.


## Обновление v1.13.4 — появление модели в штатном каталоге ПКТ

После регистрации готовой модели не нужно перезапускать Foundry. Откройте раздел Cyberpunk Remaster **«Готовые модели ПКТ»**. Конструктор отслеживает динамическое построение этого списка и автоматически добавляет пользовательские модели в ту же область, где находятся Raven, Dynalar, Militech и другие штатные комплекты.

Если окно уже было открыто во время создания модели, оно обновится автоматически. Пользовательская модель должна появиться перед первой штатной моделью.

# Нативные готовые модели ПКТ (v1.13.5)

Начиная с v1.13.5 пользовательская готовая модель ПКТ работает через тот же механизм, что штатные Raven, Dynalar, Militech и другие модели Remaster.

Это важно: состав модели больше не должен оформляться обычным текстовым списком в описании корпуса. Компоненты модели — это реальные Items Remaster, которые устанавливаются на персонажа.

После установки:

- базы появляются в разделе «Базы» ПКТ;
- модули автоматически привязываются к подходящим базам по `pktParentFamily`;
- компоненты модели получают блокировку `pktLocked`;
- отдельный компонент нельзя извлечь или деактивировать вручную;
- сначала надо открыть карточку модели в «Готовые модели ПКТ» и нажать «Демонтировать»;
- корпус нельзя снять, пока компоненты готовой модели установлены;
- подтверждение установки показывает список устанавливаемых компонентов, цену, общую Потерю Человечности и пояснение про Hard Cost.

## Структурированные пререквизиты

Для пакетных ПКТ можно передать массив `pktPrerequisites`. Каждая запись может содержать:

- `name` — читаемое имя;
- `itemId` — ID Item в compendium Remaster;
- `uuid` — полный UUID источника;
- `quantity` — количество;
- `family` — семейство базы/компонента;
- `parentFamily` — к какой базе должен привязаться модуль;
- `stress` — `waived` для базовой части готового ПКТ или `normal` для обычного Stress;
- `replaceableBase` — является ли база заменяемой;
- `locked` — блокировать ли отдельное извлечение.

Записи со `stress: integrated` и без Item ID считаются встроенной особенностью самого корпуса. Они не создаются отдельным Item: их механика должна находиться в Rule Elements/описании самого корпуса.

## Варианты выбора

`pktPrerequisiteChoices` позволяет сделать штатные строки «Выбор» в карточке готовой модели. Если нужно выбрать несколько компонентов, CIC создаёт несколько отдельных строк выбора, потому что штатный интерфейс Remaster использует один select на один выбор.


## Управление созданными пользовательскими моделями ПКТ

Начиная с версии **1.13.7**, пользовательские готовые модели ПКТ можно удалять прямо из конструктора. Откройте вкладку **ПКТ / совместимость** и найдите блок **«Зарегистрированные пользовательские модели ПКТ»**. У каждой модели показаны название, минимальное качество корпуса, цена и состояние установки. Нажмите **«Удалить»**, чтобы убрать только регистрацию готовой модели из каталога Remaster. Сам корпус/Item мира не удаляется.

Если модель уже установлена на персонаже, удалить её регистрацию нельзя. Сначала откройте вкладку Хром персонажа и нажмите штатную кнопку **«Демонтировать»**, затем вернитесь в конструктор и удалите регистрацию. Это защищает персонажа от «осиротевшего» установленного комплекта.

### Цена готовой модели ПКТ

Поле **«Цена комплекта, эдди»** в конструкторе напрямую задаёт `priceEddies` штатной модели Remaster. Именно это число показывается в строке `Минимум: Полная Конверсия Тела […] · X эдди`. Если поле цены комплекта оставить пустым или равным 0, конструктор использует обычную **цену создаваемого предмета**. Цена только отображается и автоматически не списывается.


# Готовая модель ПКТ: базы и дополнительные модули (v1.13.8)

В конструкторе готовой модели ПКТ комплект теперь собирается в двух отдельных колонках.

## Базы модели

В `Механика → Пользовательская готовая модель ПКТ → Базы модели` добавляйте именно базовые импланты: кибер-глаза, кибер-руки, кибер-ноги, комплект кибер-аудио, нейролинк и другие базовые элементы. Для каждой строки можно задать Item/UUID, название, количество, семейство, режим Stress и можно ли заменять эту базу.

Самый простой способ — перетащить нужный Item из компендиума Remaster в поле UUID. Конструктор автоматически считает его `pktFamily`. Например, кибер-глаз обычно получает семейство `cyber-eye`, кибер-аудио — `cyber-audio`, нейролинк — `neural-link`.

## Дополнительные компоненты / модули

Во второй колонке добавляются модули. Для каждого модуля есть поле `База`. Это `pktParentFamily`, то есть семейство базы, к которой Remaster должен прикрепить модуль после установки. Если перетащить штатный модуль Remaster, подходящая база выбирается автоматически. При необходимости её можно поменять вручную.

Примеры: глазной модуль → `cyber-eye`; аудиомодуль → `cyber-audio`; модуль киберруки → `cyber-arm`; модуль киберноги → `cyber-leg`; модуль нейролинка → `neural-link`.

## Предпросмотр

В `Предпросмотр` есть три вкладки: `Предмет`, `Базы`, `Доп. компоненты`. На вкладке `Базы` показываются все базовые импланты и их количество. На вкладке `Доп. компоненты` показывается каждый модуль, количество и выбранная для него база.

## Что происходит после установки модели

Все базы и модули попадают в один нативный installation plan Cyberpunk Remaster. После создания Items Remaster выполняет свою штатную привязку модулей к базам. Поэтому модуль с `pktParentFamily: cyber-audio` автоматически появляется внутри созданного комплекта кибер-аудио, модуль `cyber-eye` — внутри кибер-глаза и т. д.

## Удаление пользовательской модели

Кнопка удаления регистрации пользовательской модели показывается только Мастеру. Игроки не могут удалить модель из каталога. Уже установленную модель сначала нужно демонтировать штатной кнопкой Remaster.


## Предпросмотр Hard Cost готовой модели ПКТ

Во вкладке **Предпросмотр → Hard Cost** конструктор отдельно показывает четыре значения:

1. **Базовый корпус ПКТ** — Hard Cost самого создаваемого корпуса, то есть значение поля `Hard Cost` на вкладке «Основное».
2. **Базы модели** — сумма Hard Cost всех выбранных баз с учётом количества.
3. **Доп. компоненты** — сумма Hard Cost всех модулей с учётом количества.
4. **Итого Hard Cost модели** — сумма трёх предыдущих значений.

Ниже итогов выводится подробный расчёт по каждому Item, например `Кибер-глаз × 2 — 2 × 2 = 4`. Hard Cost считывается из Item Cyberpunk Remaster автоматически, когда Item перетаскивается в конструктор или когда UUID подтверждается в поле компонента.


## Изменения v1.13.10: гибкий состав ПКТ

В редакторе готовой модели ПКТ разделы **Базы** и **Доп. компоненты** теперь открываются отдельными внутренними вкладками. Для каждого Item можно выбрать семейство, количество, режим Stress и режим Hard. При вставке UUID или `@UUID[...]` конструктор сам пытается найти Item и заполнить его название, семейство, родительскую базу и исходный Hard Cost.

### Hard Cost компонента
- **Считать** — Item сохраняет собственный Hard Cost и уменьшает максимум Человечности как обычно.
- **Не считать** — при установке пользовательской готовой модели Hard Cost этого компонента становится 0. В предпросмотре исходный Hard остаётся виден, но его вклад в итог равен 0.

### Отдельный демонтаж
Дополнительный модуль с включённым **«можно снять отдельно»** не получает блокировку `pktLocked`. Его можно демонтировать отдельно на вкладке «Хром». Базы модели не предназначены для простого удаления: для стандартных семейств `cyber-arm`, `cyber-leg`, `cyber-eye`, `cyber-audio`, `neural-link` используйте штатную строку **«Замена базы ПКТ»**.

### Ранее установленные пользовательские модели
После обновления до v1.13.10 Мастер автоматически получает миграцию: небазовые компоненты ранее установленных CIC-моделей разблокируются, а стандартные базы получают `pktReplaceableBase=true`. Штатные модели Remaster не изменяются.


## Лимиты внутренних и внешних имплантов (v1.13.13)

На персонаже действует общий лимит установленных имплантов по двум категориям:

- **без установленного корпуса ПКТ:** до **7 внутренних** и до **7 внешних** имплантов;
- **с установленным корпусом ПКТ:** до **14 внутренних** и до **14 внешних** имплантов.

На вкладке **Хром** рядом с заголовками **ВНУТРЕННИЕ** и **ВНЕШНИЕ** отображается счётчик `установлено/лимит`, например `4/7` или `11/14`. При попытке установить новый внутренний/внешний имплант сверх доступного лимита Foundry отменит установку и покажет причину.


### Пользовательские базы в «Замена базы ПКТ»
База, созданная в Конструкторе имплантов, может использоваться как замена уже установленной базы готовой модели ПКТ. Для этого Item должен иметь тип **База**, семейство ПКТ и не быть уникальной базой. В v1.13.14 обычные базы конструктора по умолчанию создаются как доступные для замены.

В выпадающем списке замены рядом с названием пользовательской базы показываются три ёмкости: обычные слоты модулей, **внутренние места** и **внешние места**. Эти же значения отображаются на установленной пользовательской базе.

Базы, сохранённые внутри пользовательской готовой модели ПКТ, также могут использоваться в списке замены — отдельный Item мира для этого больше не обязателен. **Уникальная база** в этот список не попадает.


## Скрытая вместимость базы (v1.13.15)
Поля **Внутренние слоты базы** и **Внешние слоты базы** остаются параметрами механики конструктора и сохраняются во flags Item, однако их значения больше не печатаются на карточке импланта, в строке замены базы или на установленной базе. Это сделано, чтобы лист Хрома не перегружался служебными числами. Настраивать значения по-прежнему можно в самом Конструкторе имплантов.


## Управление размером окна конструктора

В правой части заголовка конструктора рядом с кнопкой **«Мануал»** находятся три кнопки управления окном:

- **Свернуть** — оставляет только компактную строку заголовка. Все введённые данные остаются в форме и не теряются. Чтобы продолжить работу, нажмите **«Обычный размер»** или **«На весь экран»**.
- **Обычный размер** — возвращает окно к последнему обычному размеру и позиции. Если вы до этого вручную растянули окно мышью, модуль постарается вернуть именно этот размер.
- **На весь экран** — разворачивает конструктор почти на всю рабочую область Foundry. Это удобно для больших списков ПКТ, Rule Elements и предпросмотра.

В обычном и свернутом режиме окно можно перетаскивать за свободную область заголовка. В обычном режиме его также можно растягивать за край/угол. Двойной щелчок по свободной части заголовка быстро переключает обычный и полноэкранный режим.


## Лимит стилевых имплантов

Раздел **«СТИЛЕВЫЕ»** имеет отдельный глобальный лимит: максимум **7 установленных стилевых имплантов** на персонажа. Этот предел не зависит от наличия Полной Конверсии Тела: без ПКТ и с ПКТ лимит одинаков — 7. В заголовке раздела лист показывает текущее заполнение, например `СТИЛЕВЫЕ 3/7`. Если установка нового стилевого импланта превысит предел, модуль отменит установку и покажет причину.


## Исправление установки и удаления в v1.13.20
При установке пользовательской модели конструктор очищает служебные идентификаторы исходных Item перед созданием компонентов на Actor. Это необходимо, если компонент был взят из Compendium, мирового Item или JSON-снимка: старый `compendiumSource` не должен переноситься в новый embedded Item.

Удаление пользовательской модели доступно Мастеру как в конструкторе, так и в каталоге готовых моделей ПКТ. Если Remaster динамически перерисовал карточки, кнопка всё равно работает за счёт единого обработчика. Уже установленную модель сначала нужно демонтировать.


## Предпросмотр общего Stress Cost и стоимости ПКТ (v1.13.21)

Во вкладке **Предпросмотр** есть два дополнительных расчёта. **Stress Cost** складывает Stress создаваемого корпуса, всех баз и дополнительных компонентов. Для каждой базы/модуля учитывается количество и переключатель «Stress: считать / не считать». Кнопка **«Прокинуть общий Stress Cost»** делает один общий бросок всех d6/d4.

Вкладка **Стоимость** показывает цену корпуса, всех баз и всех дополнительных компонентов с учётом количества. Отдельно выводятся **«Комплект без корпуса»** и **«Полная стоимость ПКТ»**. Кнопка **«Подставить цену комплекта (без корпуса)»** записывает сумму баз + модулей в поле «Цена комплекта, эдди», поскольку штатный каталог Remaster показывает цену готовой модели без стоимости корпуса.


## Значения компонентов при установке готовой модели ПКТ

Начиная с v1.13.24, значения в строках **Базы** и **Доп. компоненты** являются фактическими значениями установленного через модель экземпляра Item. Если вы изменили цену, Hard Cost или Stress Cost, установленный компонент получает именно эти значения.

- **Hard → Считать**: используется указанное в строке значение Hard Cost.
- **Hard → Не считать**: установленный компонент получает Hard Cost 0.
- **Stress → Считать**: используется указанная формула Stress Cost.
- **Stress → Не считать**: установленный компонент получает Stress Cost 0.
- **Цена, эдди**: записывается в цену установленного компонента.

Это предотвращает повторное применение исходных Hard/Stress из Compendium после установки и последующего пересчёта Humanity.


### Заряды активаций
Для ограниченных активаций (`раз в день`, `раз за столкновение`, `N раз за период`) конструктор использует нативный счётчик Action SF2e. Число вида `1/1` или `2/3` является текущим количеством зарядов. Маленькая кнопка-молния работает, пока текущее значение больше нуля. Когда SF2e, отдых или Мастер восстановит `system.frequency.value`, кнопка разблокируется автоматически. При нуле зарядов кнопка остаётся на листе, но становится неактивной.
