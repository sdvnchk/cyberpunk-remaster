# SF2E Cyberpunk Remaster

**SF2E Cyberpunk Remaster** — модуль для киберпанк-кампаний на
**Starfinder Second Edition** в Foundry VTT. Он добавляет снаряжение, оружие,
броню, боеприпасы, импланты, класс Нетраннера, правила Сети и Полной Конверсии
Тела, а также отдельный интерфейс управления кибервэром на листе персонажа.

- Издание: **SF2E Cyberpunk Remaster**
- Автор: **Ogorodnik**
- Версия: **2.2.0** — изменения перечислены в [CHANGELOG.md](CHANGELOG.md)
- Foundry VTT: **14.360+**
- SF2e: **1.2.0+**
- Обязательный модуль: **Pathfinder Anachronism 2.2.0+**
- Рекомендуемый модуль: **PF2e Russian 2.2.0+**
- Рекомендуемый модуль: **PF2e Toolbelt 3.50.0+** — добавляет кнопку
  встроенного выстрела гранатомётам с Rule Element `ItemCast`

## Что входит в модуль

После активации появляется папка компендиев **SF2E Cyberpunk**:

| Компендий | Содержимое |
|---|---|
| **SF2E Cyberpunk Items** | Более 400 предметов: оружие, броня, боеприпасы, расходники, импланты, программы, способности и класс Нетраннера |
| **SF2E Cyberpunk Journals** | Правила Cyberpunk, справочник Нетраннера и серийные модели ПКТ |
| **SF2E Cyberpunk Macros** | «Счётчик следа» и «НЕЙРО-АРХИВ» |

Содержимое можно перетаскивать из компендиев в мир и на персонажей как обычные
документы SF2e. Внутренние ссылки уже указывают на UUID модульных компендиев,
поэтому не зависят от конкретного мира.

## Быстрый старт

1. Активируйте SF2e, Pathfinder Anachronism и этот модуль.
2. Импортируйте или перетащите нужные предметы из **SF2E Cyberpunk Items**.
3. Откройте полный лист персонажа и выберите вкладку **«Хром»**.
4. Перетащите имплант на персонажа. Модуль распознает его, установит и пересчитает
   Человечность.
5. Модули имплантов назначайте базам перетаскиванием или списком
   **«Назначить базу…»**.
6. Правила, класс и модели ПКТ открывайте из **SF2E Cyberpunk Journals**.

Наблюдатель видит вкладку без кнопок изменения. На сокращённом limited-листе
вкладка не добавляется.

# Вики игрока и ведущего

## Вкладка «Хром»

«Хром» собирает весь кибервэр персонажа в одном месте:

- показывает установленные и неустановленные импланты;
- разделяет базы, их модули и самостоятельные импланты;
- отображает занятые и свободные слоты;
- устанавливает и извлекает предметы;
- позволяет переносить модуль прямо в нужную базу;
- следит за ограничениями ПКТ и уникальных имплантов;
- показывает Текущую, Максимальную человечность и Предел;
- сохраняет позицию прокрутки при перерисовке листа.

При длинном списке сверху закрепляется компактная панель баз. Во время
перетаскивания верхний и нижний край вкладки автоматически прокручивают список,
поэтому модуль из самого низа можно донести до базы наверху.

### Типы имплантов

| Тип | Как используется |
|---|---|
| **База** | Даёт слоты и принимает совместимые модули |
| **Модуль** | Занимает слоты выбранной базы |
| **Внутренний** | Самостоятельный внутренний имплант |
| **Внешний** | Самостоятельный внешний имплант |
| **Стилевой** | Косметический имплант |

Нулевой модуль можно установить даже в заполненную базу. Слоты нормализуются до
безопасных целых значений, а очень большая вместимость не создаёт сотни
визуальных точек.

### Состояние предмета в инвентаре

После добавления кибервэра модуль помечает его физически установленным.
Для предмета типа `equipment` также выставляется штатное состояние SF2e:

```text
system.equipped.carryType = "implanted"
```

Предмет извлекается из контейнера и перестаёт занимать руки. `invested = true`
выставляется только предмету с trait `invested`: обычный имплант не должен
самопроизвольно расходовать лимит инвестирования.

Кибероружие и киберброня хранят факт физической установки во флаге модуля, но
сохраняют собственную механику экипировки SF2e. Оружие всё ещё нужно взять в
руки, а броню — надеть штатным способом.

При извлечении восстанавливается прежнее состояние предмета. При извлечении или
удалении базы её дочерние модули отвязываются безопасным пакетным обновлением.

## Человечность

Базовые формулы:

```text
Предел = 40 + модификатор Мудрости × 10
Макс = Предел − округлённый вверх (Hard Cost всех имплантов × множитель)
```

**Текущая** человечность меняется вручную и отражает Stress Cost, терапию и
другие события игры. Если Максимум уменьшается, Текущая ограничивается новым
значением и сохраняется. Последующее извлечение импланта увеличит Максимум, но
не вылечит потерянную Текущую человечность.

Состояния на вкладке:

- 70–100% — **Человек**;
- 40–69% — **Отчуждение**;
- 25–39% — **Диссоциация**;
- 1–24% — **Пре-Психоз**;
- 0% — **Киберпсихоз**.

### Rule Element `CyberpunkHumanity`

Черта или эффект может изменить Предел человечности актёра. Добавьте на вкладке
**Rules** предмета Rule Element **«Предел человечности»**.

Увеличить Предел на 10:

```json
{
  "key": "CyberpunkHumanity",
  "mode": "add",
  "value": 10
}
```

Уменьшить Предел на 10:

```json
{
  "key": "CyberpunkHumanity",
  "mode": "add",
  "value": -10
}
```

Задать Предел равным 60 независимо от Мудрости:

```json
{
  "key": "CyberpunkHumanity",
  "mode": "override",
  "value": 60
}
```

`value` принимает целое положительное или отрицательное число. Доступны
стандартные поля `predicate` и `priority`.
Модификатор применяется к Пределу **до** вычитания Hard Cost:

```text
изменённый Предел → минус Hard Cost с мировым множителем → новый Макс
```

Rule Element действует, пока черта или эффект находится на персонаже и проходит
predicate. Удаление черты не восстанавливает Текущую человечность автоматически,
но уменьшение Максимума ограничит Текущую новым значением.

## Настройки правил

GM может изменить строгость механик через **Настройки игры → Настройки
модулей → SF2E Cyberpunk Remaster**. Все параметры являются мировыми:
одинаковые правила действуют для всех игроков и персонажей текущего мира.
По умолчанию используется авторский баланс модуля.

| Настройка | Что меняет |
|---|---|
| **Разрешить несколько кибердек** | Снимает лимит одной установленной деки |
| **Разрешить несколько нейронных ускорителей** | Снимает лимит одного ускорителя |
| **Разрешить несколько корпусов ПКТ** | Позволяет одному персонажу иметь несколько активных корпусов |
| **Разрешить ПКТ-импланты без корпуса** | Не требует корпус и не извлекает такие импланты при его снятии |
| **Разрешить корпус без Биосистемы** | Снимает требование Биосистемы для корпуса и готовой модели |
| **Игнорировать вместимость баз** | Разрешает превышать количество слотов |
| **Игнорировать ограничения качества ПКТ** | Разрешает любую модель и замену базы на любом корпусе |
| **Множитель Hard Cost** | `×0`, `×0,5`, `×1`, `×1,5` или `×2` |

Ослабление лимитов не отменяет цену предметов, Stress Cost или Hard Cost.
Множитель применяется только к влиянию Hard Cost на Максимальную
человечность; значения `×1,5` и `×2` предназначены для более тяжёлых кампаний.

## Полная Конверсия Тела

ПКТ состоит из Биосистемы, корпуса и совместимых компонентов. Модуль знает шесть
качеств корпуса:

| Значение | Качество |
|---:|---|
| 0 | Серийное |
| 1 | Тактическое |
| 2 | Продвинутое |
| 3 | Превосходное |
| 4 | Элитное |
| 5 | Абсолютное |

Основные ограничения:

- корпус устанавливается только после Биосистемы;
- одновременно активен только один корпус;
- предмет с trait `pkt` требует установленный корпус;
- Биосистему нельзя извлечь, пока активен корпус;
- удаление корпуса одним пакетом извлекает все установленные ПКТ-компоненты;
- более качественный корпус подходит модели с меньшим требованием: например,
  «Близнецов» можно поставить на тактическое тело;
- обычные правила качества компонентов и вместимости баз продолжают действовать.

Кибердеки используют семейство взаимоисключающих имплантов: одновременно можно
установить только одну. Установленная дека автоматически добавляет своё
фокус-заклинание и соответствующее Очко Фокуса, а при извлечении удаляет только
созданную ею копию заклинания. «Хронос» отвечает за боевое перемещение,
«Акаша» загружает экспертные модели, а «Оракул машин» строит защитный
контрпрогноз против программ и техники.

### Серийные модели

Карточки готовых моделей появляются только после установки Биосистемы. После
установки модели остальные карточки скрываются, чтобы не загромождать вкладку.
В поставку входят 15 готовых комплектов от Cybermatrix, Dynalar, Militech,
Moore Technologies, NovelTech, Raven Microcybernetics, Rocklin Augmentics,
Techtronika и Trauma Team. Состав, минимальное качество корпуса и точная цена
каждого комплекта перечислены в [справочнике ПКТ](docs/PKT.md), а принципы
адаптации и ценовые диапазоны — в [заметках по балансу](docs/PKT_BALANCE.md).
Отдельный [аудит бонусов](docs/PKT_BALANCE_AUDIT.md) объясняет, какие
однотипные бонусы были удалены, а какие предметы оставлены ради самостоятельной
функции.

Установка модели:

1. проверяет Биосистему и минимальное качество корпуса;
2. показывает состав и справочную цену;
3. получает исходники предметов из модульного компендия;
4. создаёт нужное количество компонентов;
5. переводит оборудование в состояние `implanted`;
6. распределяет модули по совместимым базам с проверкой слотов;
7. помечает комплектные компоненты и блокирует их обычное удаление;
8. пересчитывает максимум Человечности с учётом Hard Cost всех имплантов;
9. помещает объединённый inline-бросок Потери Человечности на страницу модели
   в журнале; игрок бросает его и изменяет Текущую Человечность самостоятельно;
10. при любой ошибке создания удаляет только предметы незавершённой операции.

Цена модели не списывается автоматически. Она равна сумме входящих имплантов
**без стоимости корпуса ПКТ**. Внутренние пометки `waived` определяют, какие
компоненты не входят в общий бросок, но интерфейс не заставляет игрока
обрабатывать импланты по одному. Готовая inline-формула находится на странице
модели в журнале. Hard Cost не объединяется и не отменяется:
каждый установленный имплант по-прежнему уменьшает максимум Человечности.

Кнопка **«Демонтировать модель»** удаляет только компоненты этой модели.
Биосистема и корпус остаются у персонажа.

### Как заменить базу модели ПКТ

У каждой стандартной заменяемой базы установленной модели появляется строка
**«Замена базы ПКТ»**:

1. выберите новый аналог в списке на карточке старой базы;
2. подтвердите цену и Stress Cost новой базы;
3. модуль создаст новую базу, перенесёт в неё все привязанные модули и удалит
   старую;
4. новая база останется частью текущей модели и будет удалена при её демонтаже.

В список попадают только базы того же семейства, равного или меньшего качества
либо максимум на одну ступень выше корпуса ПКТ. Вариант, которому не хватает
слотов для уже установленных модулей, виден, но недоступен. У уникальной базы
вместо списка показывается сообщение **«замена запрещена»**.

Стоимость не списывается автоматически. В отличие от исходной комплектации,
Stress Cost новой базы не отменяется и обрабатывается вручную. Если перенос не
удастся, модуль попытается вернуть привязки и удалить незавершённую замену.

Подробная техническая схема находится в [docs/PKT.md](docs/PKT.md).

## Оружие, броня и качество

Для оружия и брони модуль показывает рядом со строкой `Улучшения: N`
дополнительный лимит улучшений от качества.

| Качество | Оружие | Броня |
|---|---:|---:|
| commercial | +0 | +0 |
| tactical | +0 | +1 |
| advanced | +1 | +1 |
| superior | +1 | +2 |
| elite | +2 | +2 |
| ultimate | +2 | +3 |
| paragon | +3 | +3 |

Дополнение является визуальной подсказкой и не переписывает исходный текст
предмета. Оно показывается и в полном листе предмета, и в разворачиваемом
описании предмета внутри инвентаря персонажа.

## Нетраннер и Сеть

Компендии содержат класс Нетраннера, его черты и программы, а также журнал с
правилами Сети. Модуль регистрирует необходимые homebrew traits, типы боеприпасов
и базовые категории оружия и брони.

Отобранные программы сохраняют исходные числа, проверки, урон, длительность,
усиление и остальные механические поля SF2e, но описываются как программы,
квикхаки, AR-проекции, нейровирусы и работа кибернетики. Все они имеют признак
`tech`. Когда эффект требует конкретного интерфейса или предварительного взлома,
также используются признаки `ustroystvo`, `ustroystvo-neyro`,
`ustroystvo-optika`, `ustroystvo-audio`, `ustroystvo-oruzhie` и `dostup` по
правилам страницы журнала **«Нетраннер»**.

Действие **«Сканирование интерфейсов»** позволяет Нетраннеру во время
столкновения проверить Компьютеры против КС взлома цели. При успехе ведущий
называет только совместимые признаки программ — например,
`Устройство:Нейро` или `Устройство:Оптика`. Сканирование не сообщает названия,
модели, количество, качество, уровень, состояние или описания имплантов, не
даёт Доступ и не заменяет киберсканер. Полученный список действует только до
конца текущего столкновения.

Действие открывается по UUID из журнала и классовой черты **«Взлом»**, но не
копируется на лист персонажа и не занимает место в панели PF2e HUD.

Макрос **«Счётчик следа»** хранит значение в данных текущего персонажа, а
**«НЕЙРО-АРХИВ»** предоставляет связанную игровую механику издания. Перед первым
использованием перенесите макрос на панель быстрого доступа.

## Миграция старых миров

Активный GM один раз запускает скрытую миграцию, которая:

- переносит данные старого namespace `cyberpunk-cyberware`;
- синхронизирует установленное оборудование с `carryType: implanted`;
- сохраняет связи модулей с базами и удаляет устаревшие дубликаты параметров,
  уже записанных в описании;
- очищает устаревшие и осиротевшие `parentId`;
- разрешает конфликты нескольких корпусов и нейронных ускорителей;
- разрешает конфликты нескольких кибердек и других взаимоисключающих модулей;
- извлекает недопустимые ПКТ-компоненты без Биосистемы;
- ограничивает и сохраняет Текущую человечность.
- убирает ранее выданную копию **«Сканирования интерфейсов»** с листа, оставляя
  действие доступным через журнал.

Нормализация учитывает текущие мировые настройки: разрешённые мастером
сочетания не удаляются.

Старые описательные флаги сохраняются только у предметов, в описании которых
ещё нет соответствующей разметки.

# Вики автора содержимого

## Как создать предмет только в текущем мире

Это самый простой способ для домашнего контента. Такой предмет будет доступен
только в этом мире и не попадёт в компендии модуля после обновления.

1. Создайте предмет нужного типа в боковой панели Foundry:
   `equipment`, `weapon`, `armor`, `consumable`, `feat` и т. п.
2. Заполните системные поля SF2e: уровень, цену, traits, урон, КБ, использование
   и описание.
3. Назначьте иконку из мира или из
   `modules/cyberpunk-remaster/assets/icons/...`.
4. Перетащите предмет персонажу и проверьте его поведение.

### Новый имплант в мире

Для совместимости со вкладкой «Хром» добавьте в описание отдельные строки:

```text
Тип импланта: База
Слоты: 4
Hard Cost: 2
```

Поддерживаемые значения типа: `База`, `Модуль`, `Внутренний`, `Внешний`,
`Стилевой`.

- У базы `Слоты` означает вместимость.
- У модуля `Слоты` означает занимаемое место.
- У самостоятельного импланта значение слотов обычно не требуется.
- `Hard Cost` учитывается только пока имплант установлен.
- Для `equipment` выберите usage `implanted`.
- Добавляйте trait `invested` только когда имплант действительно должен
  расходовать системный лимит инвестирования.
- Для ПКТ-компонента добавьте trait `pkt`.

Кибероружию и киберброне оставьте штатное использование их типа: модуль отдельно
запомнит физическую установку, не ломая экипировку SF2e.

### Новая черта человечности

Создайте `feat` или `effect`, откройте вкладку **Rules** и добавьте
`CyberpunkHumanity` из примеров выше. Черта должна находиться на персонаже.

### ПКТ только в мире

Отдельные импланты с trait `pkt` можно создавать в мире и собирать вручную.
Автоматическая кнопка установки целой серийной модели читает структурированные
данные из модульного компендия журналов, поэтому новая готовая модель требует
добавления в исходники модуля и пересборки.

## Как добавить предмет в сам модуль

Foundry хранит рабочие компендии в LevelDB, а сборка хранит их переносимую
текстовую копию в JSON:

| Файл | Назначение |
|---|---|
| `items-export.json` | Все Item-документы |
| `journals-export.json` | Журналы и страницы |
| `macros-export.json` | Макросы |
| `data/item-folders.json` | Папки компендия предметов |
| `data/pkt-models.json` | Серийные комплекты ПКТ |
| `data/pkt-components.json` | Семейства и качества заменяемых компонентов ПКТ |

Вручную поддерживать обе копии не требуется. Рекомендуемый рабочий процесс:

1. Разблокируйте нужный компендий модуля и работайте через интерфейс Foundry:
   добавляйте предметы, меняйте описания, папки и изображения.
2. Закройте мир, чтобы LevelDB-паки больше не записывались.
3. Выполните полный авторский цикл одной командой.

```powershell
npm run author:update
```

Команду можно запускать как из рабочей копии
`E:\User\Documents\cyberpunk-remaster`, так и прямо из установленной папки
`Data\modules\cyberpunk-remaster`. Во втором случае обёртка автоматически
переключится в рабочую копию, синхронизирует изменения из Foundry и после
проверок развернёт результат обратно. Если рабочая копия будет перенесена,
укажите её явно:

```powershell
$env:CYBERPUNK_WORKSPACE_PATH = "E:\другой-путь\cyberpunk-remaster"
npm run author:update
```

Для текущей установки пути определяются автоматически. Если Foundry будет
перенесён, их можно переопределить через `FOUNDRY_MODULE_PATH`,
`FOUNDRY_DATA_PATH` и `FOUNDRY_APP_PATH`.

`author:update` последовательно синхронизирует данные из Foundry, организует
иконки, собирает паки, запускает проверки, создаёт резервную копию текущей
установки в `.build/deploy-backups` и только после этого обновляет активный
модуль. Если сборка или тесты завершатся ошибкой, установка не выполняется.

Отдельные этапы также доступны как `npm run sync:from-foundry`,
`npm run icons:organize`, `npm run build`, `npm run audit:pkt`, `npm test` и
`npm run deploy`.

`sync:from-foundry` автоматически делает временный снимок всех трёх компендиев,
импортирует предметы, папки, журналы, страницы и макросы, переносит изменённые
файлы иконок и обновляет JSON. Новые документы добавляются автоматически —
запоминать и перечислять их ID не нужно.

По умолчанию документы, отсутствующие в Foundry, не удаляются из исходников:
это защищает содержимое от случайной синхронизации неполного пака. Чтобы
отразить намеренные удаления:

```powershell
$env:SYNC_ALLOW_DELETIONS = "1"
npm run sync:from-foundry
```

Не копируйте отдельные `.ldb` и `MANIFEST` между версиями пака: переносите
целиком готовый каталог после сборки.

### UUID внутренних ссылок

Используйте стабильный ID документа и полный UUID:

```text
@UUID[Compendium.cyberpunk-remaster.cyberpunk-items.Item.<ITEM_ID>]{Название}
@UUID[Compendium.cyberpunk-remaster.cyberpunk-journals.JournalEntry.<JOURNAL_ID>]{Название}
@UUID[Compendium.cyberpunk-remaster.cyberpunk-journals.JournalEntry.<JOURNAL_ID>.JournalEntryPage.<PAGE_ID>]{Страница}
@UUID[Compendium.cyberpunk-remaster.cyberpunk-macros.Macro.<MACRO_ID>]{Макрос}
```

Сборка также переписывает известные старые world-UUID и относительные ссылки,
но новые записи лучше сразу делать в каноническом формате.

### Иконки

После выбора изображения через Foundry команда `sync:from-foundry` копирует его
из вашей пользовательской библиотеки
`D:\Workspaces\FoundryVTT_StarFinder_v14.361\Data\assets\icons` в модуль,
сохраняя исходное имя файла, и записывает путь вида:

```text
modules/cyberpunk-remaster/assets/icons/<категория>/<файл.webp>
```

Используются плоские категории `abilities`, `ammo`, `armor`, `consumables`,
`implants`, `items`, `programs`, `special`, `upgrades` и `weapons`. Обычные
импланты и ПКТ используют общую категорию `implants`.
Категория определяется по положению предмета внутри компендия, а не только по
его системному типу. Сортировка меняет только папку: имя файла не
транслитерируется, к нему не добавляются название предмета или ID. Если в одной
категории встретятся два разных изображения с одинаковым именем, команда
остановится и попросит автора явно переименовать один из исходников.
Стандартная заглушка Foundry `icons/svg/item-bag.svg` не копируется и остаётся
по системному пути. То же относится к любым изображениям с путями `icons/...`,
`systems/...`, `worlds/...` и `modules/<другой-модуль>/...`: это внешние
зависимости, поэтому сортировщик не копирует их и не меняет путь.

Папка `Data/assets/icons` при этом не является системной: это авторская
библиотека исходников и именно её изображения импортируются в модуль.

Неиспользуемые изображения разрешены: их можно заранее подготовить для будущих
предметов. Ошибкой считается только ссылка на отсутствующий файл.

Файл [ICON_DESIGN_RULES.md](assets/icons/ICON_DESIGN_RULES.md) расположен рядом
с библиотекой и является обычной документацией по визуальному стилю. Он не
участвует в runtime и не считается изображением.

### Имплант в модульном компендии

Укажите в описании `Тип импланта`, `Слоты` и `Hard Cost` так же, как для
мирового предмета. Эти строки являются источником истины: вкладка «Хром»
читает их непосредственно из описания. Поэтому `Hard Cost`, тип или число
слотов можно изменить в Foundry обычным редактированием текста — скрытые
дубликаты во флагах исправлять не требуется.

Флаги `cyberpunk-remaster` используются только для внутреннего состояния:
установки, привязки модулей к базам и структуры комплектов ПКТ. Старые предметы
без текстовой разметки по-прежнему могут использовать прежние флаги как
резервный источник до их обновления.

### Оружие и броня

1. Создайте предмет штатного типа `weapon` или `armor`.
2. Заполните все обязательные системные поля SF2e.
3. Добавьте trait качества: `commercial`, `tactical`, `advanced`, `superior`,
   `elite`, `ultimate` или `paragon`.
4. Если нужна визуальная подсказка качества, добавьте в описание абзац
   `Улучшения: N`.
5. Проверьте лист предмета и фактическую экипировку на персонаже.

### Новый компонент ПКТ

Универсальные импланты, предназначенные для разных корпусов, хранятся в папке
**ПКТ → ПКТ Импланты**. Импланты, являющиеся фирменной частью только одной
модели, остаются в **ПКТ → Уникальные импланты ПКТ**.

Добавьте запись в `data/pkt-components.json`:

```json
{
  "itemId": "AAAAAAAAAAAAAAAA",
  "family": "cyber-arm",
  "quality": 1,
  "special": false,
  "replaceable": true
}
```

- `itemId` — ID предмета из `items-export.json`;
- `family` — стабильное семейство взаимозаменяемых баз;
- `quality` — числовое качество компонента;
- `special: true` отмечает нестандартную базу;
- `replaceable: false` запрещает обычную замену.

### Новая серийная модель ПКТ

1. Создайте страницу модели в журнале и сохраните её `journalId` и `pageId`.
2. Добавьте страницу в `journals-export.json`.
3. Добавьте запись в `data/pkt-models.json`.
4. Выполните `npm run build` и `npm test`.

Ссылка в обзоре «Серийные комплекты» создаётся автоматически из
`data/pkt-models.json`.

Минимальная структура:

```json
{
  "schema": 1,
  "key": "manufacturer-model",
  "name": "Производитель «Модель»",
  "journalId": "JJJJJJJJJJJJJJJJ",
  "pageId": "PPPPPPPPPPPPPPPP",
  "requiredBodyId": "BBBBBBBBBBBBBBBB",
  "bodyQuality": 1,
  "priceEddies": 10000,
  "unique": [],
  "components": [],
  "choices": []
}
```

Запись компонента модели:

```json
{
  "key": "cyber-arms",
  "itemId": "AAAAAAAAAAAAAAAA",
  "family": "cyber-arm",
  "quantity": 2,
  "stress": "waived",
  "locked": true,
  "replaceableBase": true
}
```

Для модуля, который нужно вложить в базу, укажите
`parentFamily: "cyber-arm"`. В `choices` задаются `choose`, список `itemIds`,
`stress` и `locked`.

Поле `stress` является технической частью расчёта общего броска:
`"waived"` исключает компонент, а `"normal"` добавляет его формулу
`Stress Cost`. При установке готовой модели все добавленные кубы бросаются
одновременно, без перечисления источников игроку. Сам Hard Cost сохраняется
на каждом предмете и продолжает влиять на максимум Человечности.

`priceEddies` — сумма цен всех создаваемых `unique`, `components` и выбранных
вариантов **без корпуса**. Сборка вычисляет возможные суммы и завершится ошибкой,
если цена не совпадает.

Для воспроизводимого обновления моделей, адаптированных из Cyberpunk RED,
используется:

```powershell
npm run content:add-red-pkt
```

Скрипт идемпотентно обновляет их предметы, страницы, папки и цены, но не
назначает им пользовательские иконки.

### Новое качество или новый корпус ПКТ

У готового корпуса должен быть стабильный ID. Добавьте его и числовое качество
в обе таблицы:

- `PKT_BODIES` в `scripts/lib/content.mjs` — для структурной разметки корпуса;
- `PKT_BODY_QUALITIES` в `sheets/CyberwareTab.js` — для runtime-проверок.

Затем используйте тот же ID в `requiredBodyId` модели. Если вводится новое
словесное качество, обновите также подписи интерфейса и документацию.

## Что делает сборка

`npm run build`:

- преобразует JSON-экспорты в три LevelDB-пака Foundry 14;
- переносит Folder-документы;
- рекурсивно исправляет UUID и пути иконок;
- очищает старые дубликаты описательных параметров и создаёт только
  структурные флаги ПКТ;
- добавляет структурированные модели на страницы журнала;
- выставляет публикацию **SF2E Cyberpunk Remaster**, автор **Ogorodnik**;
- очищает world ownership, пользовательские ID и старые служебные поля;
- проверяет цены моделей и целостность ссылок;
- копирует или сверяет используемые иконки.

`npm test` запускает unit-тесты механик и валидирует уже собранные паки. Для
работы с LevelDB нужен `classic-level` 3.0.0:

```powershell
npm install
```

или путь к библиотекам приложения Foundry:

```powershell
$env:FOUNDRY_APP_PATH = "D:\Workspaces\FoundryVTT_StarFinder_v14.361\App"
```

Валидатор работает с временными копиями LevelDB и не изменяет готовые паки.

## Контрольный список нового содержимого

Перед публикацией проверьте:

- документ имеет стабильный 16-символьный ID;
- все ссылки используют UUID модульных компендиев;
- иконка лежит внутри `assets/icons` и действительно используется;
- имплант содержит тип, слоты и Hard Cost;
- equipment-имплант получает `carryType: implanted`;
- оружие и броня сохраняют штатную экипировку SF2e;
- цена модели ПКТ не включает корпус;
- `npm run audit:pkt` не показывает случайных повторных записей компонентов;
- `npm run build` и `npm test` завершаются без ошибок;
- готовые каталоги `packs/*` переносятся целиком при закрытом Foundry.

## Решение частых проблем

**Нет вкладки «Хром».** Откройте полный лист персонажа SF2e. На limited-листе
вкладки нет; также проверьте активность модуля.

**Название вкладки не меняется.** Обновите модуль и перезагрузите мир без кэша:
вкладка должна устанавливать заголовок «Хром» при каждом переключении.

**Имплант не появился во вкладке.** Проверьте строку `Тип импланта`, usage
`implanted` или `Hard Cost`.

**Имплант не стал установленным.** Для `equipment` проверьте
`system.equipped.carryType`; у оружия и брони физическая установка хранится
отдельно от состояния «в руках/надето».

**Модуль не входит в базу.** Проверьте тип, семейство базы, свободные слоты и
ограничения ПКТ.

**Не видны модели ПКТ.** Сначала установите Биосистему. Если одна модель уже
установлена, остальные намеренно скрыты до демонтажа.

**Модель недоступна.** Качество корпуса должно быть не ниже требования модели.

**Rule Element не меняет Предел.** Убедитесь, что он находится на черте или
эффекте самого персонажа, ключ написан как `CyberpunkHumanity`, predicate
проходит, а значение разрешается в число. После изменения переоткройте лист.

**У гранатомёта нет кнопки встроенного выстрела.** Активируйте рекомендуемый
модуль PF2e Toolbelt: именно он предоставляет Rule Element `ItemCast`.

**Изменения пропали после сборки.** Сначала закройте мир и выполните
`npm run sync:from-foundry`: команда перенесёт изменённые в Foundry документы и
пути иконок в экспортные исходники. После этого запускайте сборку.
